## 次回フィードバック用メモ

### 配色・テーマ

- ライト / ダークの変数は、ページ背景用の文字色とカード面用の文字色を分ける。ダーク背景のヒーローは明色、明るいカード面は濃色に固定する。
- 黄色のような明るいアクセント面では、ダークモードでも文字を濃色に明示する。親要素の白文字を継承させない。
- テーマ切替の遷移は、ページ背景と追従ヘッダー背景を同じ時間で揃える。片方だけ即時切替にすると時間差が目立つ。
- 追従ヘッダー下部の下線や影は、テーマ遷移中に黒線として見えやすい。必要性が低ければ撤去し、背景と同色の余白だけで下のコンテンツを覆う。

### レイアウト

- 写真が縦長なら、横長の `object-fit: cover` フレームに押し込まない。SPは縦長寄りの比率にし、PCは名前と写真を同じファーストビューの2カラムにして、写真の意図を一目で伝える。
- PCで中央コンテナからはみ出す追従ヘッダーは、背景だけを画面幅に広げる。ヘッダー内のロゴや操作は本文と同じ左右端に揃える。
- 追従ヘッダーは、カルーセルやカードの影より確実に上のレイヤーに置く。背景を不透明にし、ヘッダー幅を画面端まで確保する。
- 同じ変更をPCだけで終わらせない。SPでも名前、バースト、ヘッダー、カルーセル、固定ボタンが重ならないかを確認する。

### 装飾・動き

- 装飾には必ず意味を持たせる。星形バーストは単なる `POP!` ではなく、プロフィールや活動を要約する短いメッセージにする。
- 流れるキーワードは固定帯より、写真の上に重なる斜めテープなど、コンテンツと関係する場所に置く。ただし写真やカルーセル操作を隠さない。
- バーストのような絶対配置の要素は、名前・写真・ヘッダーのどれに属するかを決める。PC/SPのどちらでも文字やヘッダーに重ならない位置を個別に設計する。
- 回転した要素は、指定した `top` より見た目の上端がずれる。実際の表示境界で位置を確認する。

### 実装・確認

- 雛形を置き換える際は、既存のCSS変数やスタイルがファイル末尾に残っていないか確認する。後ろに残る定義はテーマを上書きし、見た目の不具合につながる。
- 画面ごとの確認は、計算済みスタイルだけで完了にしない。PC / SP、ライト / ダーク、スクロール後の追従ヘッダーをスクリーンショットで確認してから完了とする。

### 追加チェックリスト

- 各テーマで、本文・見出し・補足テキスト・リンク・ボタン・カード上の文字を個別に見る。背景の色だけでなく、文字の継承先まで確認する。
- 画面幅は少なくともSP幅、PC幅、切替境界付近で確認する。SPでは長い名前や肩書き、PCでは横に広がる実績カードや見出しがはみ出していないかを見る。
- 読むための文字に過度な負の文字間隔や極端な行高を使わない。大きな表示文字でも、実際の日本語の字形が欠けたり接触したりしていないかを確認する。
- カルーセルは写真の表示だけでなく、前後ボタン、ドット、現在位置の表示、テープの重なりを確認する。自動切替は操作中の状態を壊さないようにする。
- 固定・追従する要素は、SPの安全領域、ヘッダー、トップ復帰ボタン、カルーセル操作と互いに重ならないかを確認する。
- `z-index` は必要な箇所だけに設定し、層の役割を決める。追従ヘッダー、固定ボタン、写真上の操作、装飾、本文の順を曖昧にしない。
- ホバー表現だけに状態を依存させない。SPでリンクやボタンが操作できる大きさか、キーボード操作時にフォーカスが見えるかも確認する。
- `prefers-reduced-motion` では流れるテープ、自動カルーセル、入場演出が負担にならないかを確認する。
- 外部フォント・外部画像に頼らない要件では、ネットワークなしでもレイアウトが崩れない標準フォント構成にする。
- 情報の優先度を崩さない。装飾は名前、肩書き、写真、リンクより先に目立たず、読みやすさを損ねるなら削る。

### ワークショップ用ガードレール

- 編集対象は `starter/index.html`、`starter/style.css`、`starter/script.js`、`starter/REQUIREMENTS.md` と `starter/assets/` のみ。`docs/`、`examples/`、`guide/`、`.github/workflows/` は編集しない。
- 実装は本人の要件が確認されてから始める。未確認の名前、肩書き、写真、リンク、紹介文をプレースホルダーで補完して完成扱いにしない。
- 静的HTML / CSS / JavaScriptだけで作る。フレームワーク、ビルドツール、ライブラリ、参加者側での追加インストールを必要とする確認ツールは追加しない。
- ブラウザ確認は、参加者が `starter/index.html` を開いて行える状態を前提にする。エージェント側で使えるブラウザ自動化は補助であり、参加者にPlaywrightなどを入れさせない。
- 修正は問題の原因になっている1つの箇所から小さく行い、修正直後に対象の画面幅・テーマ・操作だけを再確認する。関係ないデザインやファイルを同時に作り直さない。
- 完了前に、ライト / ダーク、SP / PC、リンク、テーマ切替、写真カルーセル、追従・固定要素を確認する。PC対応を選ばない場合はSP確認を優先する。
